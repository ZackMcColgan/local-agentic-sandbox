## Executive Summary

1. **Multi-round narration collapses into an unreadable wall that overwrites the final summary (U1 — X1, Lock #7).** Three stacked bugs glue intermediate tool-round chatter together with missing whitespace (`"patch:Now"`, `"file:Host"`), collapse single newlines in `ReactMarkdown`, and permanently prepend all intermediate narration onto the settled assistant message—pushing `<ActivityTimeline>` off-screen during live turns and violating the lock that the final summary stays cleanly in the model's own words.
2. **Observed turns are second-class citizens across ten sibling client-state paths (U2 — X4, F6).** Runtime audit F6 (`lastActivityAtMs` gated on local `isLoading`, SSE `ping` dropped) remains unfixed at `7b205b5`, and ten sibling defects share the same root cause: observed board/cross-device streaming turns lose the Stop button, lose Queue/Steer (sending starts a colliding turn), silently stop polling forever after one transient fetch error, show `"Latest"` instead of `"Live"`, skip auto-follow on trace/thinking updates, render blank elapsed time before trace 1, never feed `liveTokPerSec` to `NowLineBar`, and drop sidebar/drawer liveness and supervisor indicators.
3. **File and diff presentation is fragmented across seven overlapping surfaces while blind to `host_replace_string` (U3 — X2, Lock #8).** Repeated writes to the same file never coalesce in Grounded File Citation Cards, `turnHostDiffs`, or `ActivityTimeline` / `CanvasDiffSheet` (causing duplicate cards, inflated counts, and duplicate React keys); Grounded File links point host paths at `/api/files?path=...` which returns HTTP 403/404; and `host_replace_string` is omitted from write classification, erasing its diffs from the timeline and undercounting `StintCard` `Files` and `+N −M`.
4. **Long (300+ round) threads thrash mobile CPU and network on every poll and token (U4 — X5, Lock #4).** While default `GET /api/threads` now returns compact summaries via `listThreadSummaries()` (contrary to older ~27 MB list captures), thread search still reads and parses every thread file on disk per keystroke, thread switches download the full multi-MB thread JSON twice back-to-back, live observation re-downloads the entire growing thread JSON every 1.5 s without ETags or visibility/view gating, a 15 s background storm polls five endpoints unconditionally, and zero memoization on `ChatMessageItem`, `ActivityTimeline`, and `StintCard` (`JSON.stringify` on every trace result per render) causes O(M × T) work on every frame.
5. **Light mode is half-built and violates WCAG contrast floors and the emerald-only accent lock across 20+ files (U5, U6, U8 — X3, Locks #1, #3).** Four entire surfaces (`BoardView`, `BoardAddSheet`, `CanvasDiffSheet`, `ExplorerPanel`) plus six inline badges/pills are hardcoded dark-only; light-mode labels routinely drop to `1.9:1–2.56:1` contrast (`text-emerald-400`, `text-slate-400`, `text-zinc-400`); dark-mode text violates the `zinc-400` floor in seven locations; and blue user chat bubbles, cyan running chips, indigo/purple/teal accents, and non-disconnect amber appear throughout because `tests/accentContrastAudit.test.ts` scans only 2–3 files.
6. **Multiple shipped controls are silent no-ops, phantom runners, or dishonest telemetry (U7, U9, U10, U13–U16 — X4, X6).** Manual compaction (`{ action: "compact" }`) and per-thread model/effort persistence (`{ action: "setModel" }`) POST to `/api/threads/[id]`, which has neither handler; Project **Run Now** and **Schedule 2:00 AM** pass `executeInline: false` and create permanently stuck `"running"` phantom tasks with zero worker or schedule; Morning Report **Revert** / **Submit** flags are unwired; Skills **View SKILL.md** fabricates fake markdown with hardcoded `confidence: 0.94`; four live scheduler APIs have zero UI; and header/personal-name design locks (#5, #6) are breached in `ChatStream.tsx` and `app/layout.tsx:28`.

## Detailed Findings

### U1 — Narration Wall, Whitespace-Eating Segment Joins, and Intermediate Chatter Glued onto Final Summary

- **Exhibit / Lock:** Exhibit X1 · Design Lock #7 (final summary paragraph stays in the model's own words)
- **Risk:** Likelihood 5 × User Harm 5 = **25**
- **Evidence:**
  - `web-ui/lib/liveActivity.ts:113-123` (`appendNarrationChunk`): inserts a separator only when `/[.!?]["')\]]*$/.test(existing) && /^[A-Z]/.test(chunk)`, and even then inserts only a single `"\n"`.
  - `web-ui/lib/chat/roundLoop.ts:1004-1007` & `web-ui/lib/chat/turnEngine.ts:440`: feed live round tokens into `appendNarrationChunk` before calling `streamSnapshot.maybeWrite`.
  - `web-ui/components/ChatStream.tsx:1083-1093`: interactive SSE loop executes `accumulatedRawContent += event.content || ""` with zero inter-round separator.
  - `web-ui/lib/chat/roundLoop.ts:1285-1287, 1995-2002` & `web-ui/lib/chatUtils.ts:28-35` (`joinNarrationChunks`): joins every tool-round's intermediate prose with a single space (`"${existing} ${incoming}"`) and prepends `carriedToolRoundProse` directly onto `currentAssistantMessage.content` before the final summary.
  - `web-ui/components/chat/messageRender.tsx:546-658`: renders `m.content` through `<ReactMarkdown>` without `remark-breaks`, collapsing single `\n` characters to spaces.
  - `web-ui/components/chat/messageRender.tsx:359, 370` & `web-ui/components/ActivityTimeline.tsx:39`: sets `activelyThinking = isStreaming && !hasContent`, collapsing the thinking preview as soon as round-1 narration lands while intermediate prose grows beneath `<ActivityTimeline>`.
  - `web-ui/lib/threads/threadStore.ts:888`: thread-list `lastMessagePreview` inherits the glued intermediate prose.
- **Mechanism:**
  1. When round 1 ends with a colon, backtick, or non-sentence punctuation (e.g., `"Let me apply the patch:"` followed by round 2 `"Now running tests..."`), `appendNarrationChunk` fails the `/[.!?]/` test and concatenates them directly into `"patch:Now"` / `"file:Host"`.
  2. When round 1 does end in `.`, `appendNarrationChunk` inserts a single `\n`, which CommonMark (`ReactMarkdown`) folds into a single space—merging every round into one continuous wall of prose.
  3. On interactive SSE turns, `ChatStream.tsx:1084` does not insert any boundary between rounds at all.
  4. On turn settlement, `roundLoop.ts:1999` permanently concatenates `carriedToolRoundProse` onto `currentAssistantMessage.content` ahead of the final summary, so reloading the thread preserves the wall forever.
- **Blast Radius:** Every multi-round turn across four surfaces: live observed board turns, live interactive SSE turns, settled assistant messages in chat history, and thread-list previews. On mobile, the growing prose block pushes `<ActivityTimeline>` above the viewport under auto-follow, turning a 50-round run into an unreadable paragraph wall.
- **Fix Shape:**
  1. Separate **intermediate round narration** from the **final assistant response** in the message schema (e.g., attach each round's brief commentary to its round/trace segment or `roundNarrations?: Array<{ round: number; text: string }>`), keeping `currentAssistantMessage.content` strictly for the final summary paragraph (Design Lock #7).
  2. In `appendNarrationChunk` (`lib/liveActivity.ts:113-123`) and `ChatStream.tsx:1084`, insert an explicit paragraph break (`"\n\n"`) on every round boundary (keyed by round index or tool-call completion, never fragile trailing-punctuation regexes), and normalize missing whitespace after `[:.;!?]` when joining chunks.
  3. Keep `<ActivityTimeline>` primary during live execution; collapse or tuck intermediate narration under its round rather than letting it push the live timeline off-screen, and drive `activelyThinking` from active reasoning chunks rather than `!hasContent`.
  4. **Proving test:** Multi-round narration fixture ending with `:` and `.` across both SSE and observed snapshot paths asserts zero glued words (`patch:Now`), paragraph separation in rendered HTML, and settled `message.content` containing only the final summary.

### U2 — Observed-Turn Liveness & Control Blindness (Runtime Audit F6 + 10 Client-State Siblings)

- **Exhibit / Lock:** Exhibit X4 · Design Lock #4 (mobile is the main surface)
- **Risk:** Likelihood 5 × User Harm 5 = **25**
- **Evidence (F6 + 10 siblings of the exact same `isLoading`-only class):**
  - **F6 (still unfixed at `7b205b5`) — `web-ui/components/ChatStream.tsx:309-311, 1019-1261`:** `useEffect(() => { if (isLoading) setLastActivityAtMs(Date.now()); }, ...)` never fires for observed board/cross-device turns (`isLoading === false`), and SSE `ping` events are unhandled, falsely tripping the 30 s stalled state.
  - **Sibling 1 (No Stop button, no Queue/Steer on observed turns) — `web-ui/components/ChatStream.tsx:539, 1452-1518, 2861, 2916`:** `isGeneratingOrRunning = isLoading || isTaskActive` excludes `lastAssistant?.status === "streaming"` (observed turns). As a result, neither the Stop button (`:2916`) nor the Queue/Steer toggle (`:2861`) renders, and submitting text calls `POST /api/chat` instead of steering/queueing, starting a colliding parallel turn.
  - **Sibling 2 (Observed live poll dies permanently on one transient error) — `web-ui/app/page.tsx:492-522`:** Inside `pollLiveThread`, if `!res.ok` or `fetch` throws, the function returns/catches **without re-arming `setTimeout(pollLiveThread, 1500)`**, permanently freezing live updates on screen while the server turn keeps running.
  - **Sibling 3 (Floating follow pill says `"Latest"` instead of `"Live"`) — `web-ui/components/ChatStream.tsx:2674`:** Renders `{isLoading ? "Live" : "Latest"}`, mislabeling an active observed streaming turn as settled.
  - **Sibling 4 (Sticky `RUNNING` banner absent on observed turns & frozen elapsed timer) — `web-ui/components/ChatStream.tsx:2563-2584`:** Gated on `isLoading` only, computes `Math.floor((Date.now() - turnStartedAtRef.current) / 1000)` inline with no tick timer (freezing between chunks), and duplicates `NowLineBar`.
  - **Sibling 5 (Blank elapsed time on observed turns before trace 1) — `web-ui/components/ChatStream.tsx:300, 2329` & `web-ui/lib/turnSpeed.ts:139-142`:** `turnStartedAtRef.current` is only set on local sends; `deriveObservedStartMs(traces)` returns `null` during long initial prefill/thinking, leaving `NowLineBar` with no elapsed clock despite `activeTurn.startedAt` being available on `GET /api/threads/[id]`.
  - **Sibling 6 (`liveTokPerSec` never wired to `NowLineBar`) — `web-ui/components/ChatStream.tsx:2324-2334` & `web-ui/lib/turnSpeed.ts:49, 159-160`:** `ChatStream` omits the `liveTokPerSec` prop entirely; `computeLiveTokPerSec` has zero production callers. Speed stays blank until a full round settles.
  - **Sibling 7 (Auto-follow misses trace-only and thinking-only updates on observed turns) — `web-ui/components/ChatStream.tsx:713-747`:** The `useEffect` dependency array watches `lastMsg?.content` but omits `lastMsg?.traces`, `lastMsg?.thought`, and `lastMsg?.thinkingSegments`; line 731 uses instant `scrollTop = scrollHeight` only for `isLoading || isTaskActive`, while observed turns fall through to `distanceFromBottom <= 100`, which skips scrolling whenever a polled round adds >100 px at once.
  - **Sibling 8 (Mobile drawer active indicator never lights up) — `web-ui/components/NavigationDrawer.tsx:477` vs `web-ui/lib/threads/threadStore.ts:820-821`:** Drawer checks `thread.status === "active"`, whereas `reconcileSummaryStatus` normalizes live threads to `status: "running"`.
  - **Sibling 9 (Sidebar liveness, progress counts, and `<SupervisorStatusBadge>` silently dead) — `web-ui/components/ThreadsSidebar.tsx:327-336, 485, 503-511`, `web-ui/components/ViewShell.tsx:443-454`, `web-ui/lib/threads/types.ts:129-145`:** `GET /api/threads` returns `ThreadSummary[]`, which omits `messages`, `liveness`, `needsAttention`, `stalledReason`, `autoResumeCount`, `scope`, and `hostAccess`. All UI elements reading those fields off the thread list silently evaluate to `undefined`.
  - **Sibling 10 (Board view never refreshes after opening) — `web-ui/app/page.tsx:72-91`:** Fetches `/api/board` and `/api/board/control` once when switching to Board view with zero polling or SSE refresh, so live `working` / `done` / `needs-attention` transitions never appear unless the user leaves and re-enters Board.
- **Mechanism:** Client state was built around the local `isLoading` boolean (set only inside `handleSend` / `runApprovalContinuation`), rather than deriving a unified `isTurnLive` predicate from server truth (`activeTurn != null || lastAssistant?.status === "streaming" || isLoading`). Every component that branched on `isLoading`—or assumed full `Thread` objects on the list endpoint—silently broke once overnight/board and cross-device observation became primary workflows.
- **Blast Radius:** Every user watching a board job or opening an active session on mobile experiences frozen progress, missing Stop/Steer controls, false stall badges, and stale board/drawer statuses.
- **Fix Shape:**
  1. Define a single derived `isTurnLive` selector in `ChatStream.tsx` (`isLoading || isTaskActive || Boolean(activeTurn) || lastAssistant?.status === "streaming"`) and drive F6 activity timestamps (updated on SSE `ping`, token chunks, and observed poll record `updatedAt`), Stop button, Queue/Steer composer, floating `"Live"` pill, and auto-follow from it; remove the duplicate sticky `RUNNING` banner (`:2563-2584`).
  2. Pass `activeTurn?.startedAt` into `NowLineBar` elapsed derivation and wire `computeLiveTokPerSec` during streaming rounds.
  3. Re-arm `pollLiveThread` in a `finally` block with bounded backoff (reusing `lib/reconcilePollPolicy.ts` conventions) while gating on `activeNavView === "sessions"` and `!document.hidden`; add a lightweight visibility-gated poll on `BoardView` when active.
  4. Project `liveness`, `needsAttention`, `stalledReason`, `autoResumeCount`, `scope`, and `traceCount` onto `ThreadSummary`, and fix `NavigationDrawer.tsx:477` to check `status === "running" || status === "active" || hasStreamingMessage`.
  5. **Proving test:** Observed-turn render test (`isLoading = false`, `lastAssistant.status = "streaming"`, `activeTurn.startedAt` set) asserts Stop button visible, Steer/Queue active, `"Live"` pill, live elapsed clock, non-stalled state across polls, and poll recovery after a rejected fetch.

### U3 — Uncoalesced Duplicate File Cards, Overlapping Trace/Diff Surfaces, Broken Host Links, and `host_replace_string` Blindness

- **Exhibit / Lock:** Exhibit X2 · Design Lock #8 (stint card shows only derivable metrics accurately)
- **Risk:** Likelihood 5 × User Harm 4 = **20**
- **Evidence:**
  - **Uncoalesced Grounded File Citation Cards & broken host URLs — `web-ui/components/chat/messageRender.tsx:884-950` & `web-ui/app/api/files/route.ts:112-115`:** `m.traces.filter(t => Boolean(t.args?.path) || ...).slice(0, 3)` renders up to 3 uncoalesced cards for the exact same file touched in consecutive rounds, shows zero diff context, and builds `"Open file"` with `resolveSvgUrl(pathLabel)` (`/api/files?path=...`). In `api/files/route.ts:112-115`, `confinePathToRoot` rejects any absolute host path outside the sandbox roots with HTTP 403/404.
  - **Uncoalesced `turnHostDiffs` — `web-ui/lib/chat/roundLoop.ts:537-539, 1604-1606, 2066`:** Every `host_write_file` / `host_replace_string` call pushes a new entry into `turnHostDiffs` without merging by normalized path, so 4 edits to `foo.ts` persist 4 separate `TurnFileDiff` objects in `message.diffs`, inflating `CanvasDiffCard` (`messageRender.tsx:825-882`) counts and tabs.
  - **Uncoalesced `ActivityTimeline` / `CanvasDiffSheet` & duplicate React keys — `web-ui/components/ActivityTimeline.tsx:402-405` & `web-ui/components/CanvasDiffSheet.tsx:98-114`:** `allTurnDiffs` collects every write row's diff without coalescing by `filePath`, and `CanvasDiffSheet.tsx:102` renders file-switcher chips with `key={d.filePath}`, triggering React duplicate-key warnings and duplicate chips for the same file.
  - **`host_replace_string` invisible to timeline, diff sheet, and `StintCard` — `web-ui/lib/activityTimeline.ts:118-127`, `web-ui/lib/chatUtils.ts:489-493`, `web-ui/lib/stintDerivation.ts:189`, `web-ui/lib/hostMode.ts:500-502`:** `classifyToolKind` matches `write|edit|patch|create_file|delete_path|replace_in_file` and omits `host_replace_string` (the preferred host edit tool). Consequently, `host_replace_string` classifies as `"other"` (`"Ran host replace string"`), produces no inline write diff in `ActivityTimeline` / `CanvasDiffSheet`, is skipped by `extractFileWriteDiffsFromTraces`, and is **excluded from `StintCard`'s `Files` count and `+N −M` line totals**.
  - **Seven overlapping trace/file surfaces on one message — `web-ui/components/chat/messageRender.tsx:365, 384-497, 730-757, 762-823, 825-882, 884-950` & `web-ui/components/ChatStream.tsx:2476-2514`:** A single turn can simultaneously render: (1) `<ActivityTimeline>` with inline mini-diffs, (2) legacy `m.traces` "Details · Expand Proof" cards, (3) legacy `live-trace-rows` panel, (4) `extractCodeDeliverablesFromMessage` full-file code cards, (5) `m.attachments` download cards, (6) `CanvasDiffCard`, and (7) Grounded File Citation Cards. Meanwhile, `extractFileWriteDiffsFromTraces` (`lib/chatUtils.ts:508-532`) prefixes every line of `host_write_file` with `+ ` and `removedLines: 0` (no pre-image context).
- **Mechanism:** New UI surfaces (`ActivityTimeline`, `CanvasDiffSheet`, `CanvasDiffCard`) were layered onto `messageRender.tsx` without retiring older trace/citation renderers or sharing a single per-file coalesced diff model, and `host_replace_string` was added to `hostMode.ts` without updating client tool classifiers.
- **Blast Radius:** Every coding turn on host repos displays duplicate file cards for the same file, broken `"Open file"` links, inaccurate `StintCard` file/line stats, and noisy overlapping proof/diff widgets.
- **Fix Shape:**
  1. Add `host_replace_string` to `classifyToolKind` (`lib/activityTimeline.ts:118`), `extractWriteDiffFromTrace` (reconstructing unified diff from `oldString`/`newString` or persisted `message.diffs`), `extractFileWriteDiffsFromTraces` (`lib/chatUtils.ts:489`), and `deriveStintMetrics` (`lib/stintDerivation.ts:189`).
